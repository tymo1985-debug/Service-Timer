# Service Timer PWA

Лёгкое локальное PWA для учёта времени служения: таймер и паузы, ручные записи, календарь, история, цель месяца, заметки, CSV и JSON-backup. Сервер, аккаунт и тяжёлый UI-фреймворк не требуются.

## Архитектура

- `index.html` — интерфейс, переводы и экранная логика.
- `app-core.js` — модель данных, миграции, валидация, storage и операции merge/split.
- `service-worker.js` — изолированный offline-кеш только для scope Service Timer.
- `manifest.json` — установка PWA.
- `version.json` — опубликованная версия и release notes.
- `tests/app-core.test.js` — тесты миграций и арифметики длительности.

Данные сохраняются единым документом `service-timer:data` со `schemaVersion: 2`. При первом запуске автоматически читаются старые ключи `ministry-sessions` и `ministry-settings`; исходные ключи намеренно не удаляются, поэтому миграция обратимо-безопасна.

Завершённая запись хранит `elapsedMs` — реальное отработанное время без пауз. Поэтому merge суммирует фактические длительности, даже если между записями был большой промежуток, а split делит именно полезное время и сохраняет его сумму до миллисекунды. Теги хранят стабильные ID, а локализуются только при отображении и экспорте.

## Локальный запуск и проверки

Приложение нужно открывать через локальный HTTP-сервер (service worker не работает с `file://`):

```sh
python3 -m http.server 8080
```

Затем открыть `http://localhost:8080`. Автоматические тесты не требуют зависимостей:

```sh
node --test tests/app-core.test.js
```

## Выпуск версии

1. Обновить `APP_VERSION` в `index.html`.
2. Установить ту же версию в `version.json`, дату и release notes.
3. Обновить суффикс `CACHE_NAME` в `service-worker.js`.
4. Запустить тесты и ручной smoke-test ниже.
5. Опубликовать все файлы вместе. Старый worker продолжит обслуживать прежнюю оболочку, пока новая полностью не скачана; после подтверждения обновления активируется только worker текущего scope.

## Ручной smoke-test

- Обновиться поверх версии 1.2.0 с существующими записями; сверить итог месяца и теги на каждом языке.
- Запустить таймер, поставить паузу, перезагрузить страницу, продолжить и завершить.
- Объединить две завершённые записи с промежутком; итог должен равняться сумме исходных длительностей.
- Разделить запись и проверить, что сумма половин равна исходной.
- Экспортировать backup, восстановить его; отдельно проверить отказ на случайном/повреждённом JSON.
- Установить PWA, перейти offline, перезапустить и открыть все разделы.
- Если на том же origin есть другая PWA, обновление Service Timer не должно затронуть её worker или caches.
- Проверить клавиатурную навигацию, видимый focus, экранные читалки и режим reduced motion.

## Формат backup

Корневой объект содержит `schemaVersion`, `exportedAt`, `appVersion`, `sessions` и `settings`. Импорт принимает старый backup без версии, мигрирует локализованные теги и вычисляет `elapsedMs`. Неизвестные будущие версии, неверные даты, слишком крупные файлы и частично повреждённые наборы отклоняются до замены текущих данных.
